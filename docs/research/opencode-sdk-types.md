# opencode v2 SDK — Type & Route Catalog

Source: `sst/opencode` @ branch `dev`, file `packages/sdk/js/src/v2/gen/types.gen.ts` (~11,237 lines, auto-generated by `@hey-api/openapi-ts` from the OpenAPI spec). Companions: `v2/client.ts`, `v2/data.ts`, `v2/gen/client.gen.ts`.

This catalog documents every domain type and every route Data/Errors/Responses triplet. Field optionality, discriminator string literals, and union variants are preserved exactly. Long redundant repetitions (e.g. the `number | "NaN" | "Infinity" | "-Infinity"` salad that surrounds every numeric field in Effect-encoded types) are collapsed to `number /* + NaN/Infinity sentinels */` once and noted.

A note on scope: this is a structured catalog of the API surface, not a verbatim copy of the source. Where the literal token matters (discriminator tag, URL path, exact field name), it is reproduced exactly.

## 0. Client plumbing

`packages/sdk/js/src/v2/client.ts` exports:

- `createOpencodeClient(config?: Config & { directory?: string; experimental_workspaceID?: string })` — wraps `createClient` + `OpencodeClient` from `gen/sdk.gen.ts`. Adds `x-opencode-directory` and `x-opencode-workspace` headers (URL-encoding the directory) plus a request interceptor (`rewrite`) that rewrites GET/HEAD requests so the headers become query string params (`directory`, `workspace`, plus the bracket form `location[directory]` / `location[workspace]` for `/api/` v2 routes). Throws on `text/html` responses ("not supported by this version"). Routes client errors through `wrapClientError`.
- Re-exports everything from `./gen/types.gen.js` and aliases `FileSystemEntry as LocationFileSystemEntry`.
- Exports `OpencodeClient` class and `Config as OpencodeClientConfig`.

`packages/sdk/js/src/v2/gen/client.gen.ts` creates a default `client` against `http://localhost:4096`.

`packages/sdk/js/src/v2/gen/client/types.gen.ts` is just the hey-api Fetch-client framework types (`Config`, `RequestOptions`, `Client`, `ResponseStyle = "data" | "fields"`, `Options`, etc.) — generic, not opencode-specific.

`packages/sdk/js/src/v2/data.ts` exports a helper:

```ts
export const message = {
  user(input: Omit<UserMessage, "role" | "time" | "id"> & {
    parts: Omit<Part, "id" | "sessionID" | "messageID">[]
  }): { info: UserMessage; parts: Part[] }
}
```

`ClientOptions` (domain): `{ baseUrl: \`${string}://${string}\` | (string & {}) }`.

## 22. Key cross-references

### Session lifecycle (v2)

```
V2SessionCreate    (POST /api/session)         → SessionV2Info
       │
V2SessionPrompt    (POST /api/session/{id}/prompt, body: Prompt + delivery)
       │           → SessionInputAdmitted (admittedSeq + Prompt + delivery)
       │
       ├── streamed via V2EventSubscribe (GET /api/event) as the Event union:
       │      session.next.prompted → session.next.prompt.admitted → session.next.prompt.promoted
       │      → session.next.step.started
       │           → session.next.text.started/delta/ended
       │           → session.next.reasoning.started/delta/ended
       │           → session.next.tool.input.started/delta/ended
       │             → session.next.tool.called
       │             → session.next.tool.progress*
       │             → session.next.tool.success | session.next.tool.failed
       │           → session.next.shell.started/ended (if shell tools used)
       │           → session.next.step.ended | session.next.step.failed
       │      → (optional) session.next.retried
       │      → (optional) session.next.compaction.started/delta/ended
       │      → (optional) session.next.synthetic / session.next.context.updated
       │      → session.next.interrupt.requested (if user cancels)
       │      → session.idle / session.status (status: idle|busy|retry)
       │      → permission.v2.asked  (paired with V2SessionPermissionReply)
       │      → question.v2.asked    (paired with V2SessionQuestionReply / Reject)
       │
V2SessionContext   (GET /api/session/{id}/context)   → Array<SessionMessage>
V2SessionMessages  (GET /api/session/{id}/message)   → SessionMessagesResponse (cursor-paged)
V2SessionCompact   (POST /api/session/{id}/compact)  → 204
V2SessionWait      (POST /api/session/{id}/wait)     → 204
```

### Event stream consumers
- `/event` (v1) returns the `Event` union directly. SSE stream.
- `/api/event` (v2, `V2EventSubscribe`) returns the same events but typed as `string` in the generated schema (the bytes are JSON-encoded `Event` union members).
- `/global/event` returns `GlobalEvent` (Event payload wrapped with `{ directory, project?, workspace? }`).
- `SyncEvent*` variants flow through the same channel for cross-instance replication.

### Notable header / query rewriting (from `v2/client.ts`)
- Outgoing `x-opencode-directory` header → URL query `directory` (and `location[directory]` for `/api/*`).
- Outgoing `x-opencode-workspace` header → URL query `workspace` (and `location[workspace]` for `/api/*`).
- Only applied to `GET` and `HEAD` requests; the headers are stripped from the rewritten request.
- The directory value is URL-encoded once (with `encodeURIComponent`).

### Notes about identifier collisions in the generated module
The hey-api codegen sometimes appends digits to disambiguate:
- `UnknownError1` is the v2 `_tag: "UnknownError"` form (`{ _tag, message, ref? }`); `UnknownError` is the legacy `name + data` form (`{ name: "UnknownError"; data: { message; ref? } }`).
- `ProviderAuthError1` is the OAuth flow errors enum; `ProviderAuthError` is the message-time error (`{ name: "ProviderAuthError"; data: { providerID; message } }`); `ProviderAuthError2` is `ProviderAuthErrors[keyof ProviderAuthErrors]` (route error union for `GET /provider/auth`).
- `VcsApplyError` is the error object; `VcsApplyError2` is `VcsApplyErrors[keyof VcsApplyErrors]` (route error union).
- `SessionMessagesResponse` is the v2 cursor-paged response object; `SessionMessagesResponse2` is the v1 route's response variable (`{ info: Message; parts: Array<Part> }`).
- `EventTuiPromptAppend` etc. (no suffix) lack an `id` — they're the *publish* body for `POST /tui/publish`. `EventTuiPromptAppend2` etc. carry `id` — they're the broadcast/SSE form on `/event`.
- `PtyConnect*` (v1) is declared at the very end of the file after the v2 routes (around line 11203+), separately from `V2PtyConnect*`.
